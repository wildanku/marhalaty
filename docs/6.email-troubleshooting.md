# Email Troubleshooting & Configuration

## 🚨 CRITICAL: Queue Issue (Most Common Problem)

**If email returns 200 OK but never arrives, check your queue configuration:**

```bash
# Run diagnostic command
php artisan debug:email-queue
```

**The Problem:**

- Default `config/queue.php` uses `'database'` driver
- Emails are **queued to jobs table**, not sent immediately
- They need `php artisan queue:work` process to actually send them
- If queue:work isn't running, emails stay stuck in database forever ❌

**The Solution (Pick One):**

#### Option 1: Use Sync Queue (Recommended for Email Tester)

```env
QUEUE_CONNECTION=sync
```

Then clear cache:

```bash
php artisan config:clear
php artisan config:cache
```

#### Option 2: Run Queue Worker

```bash
# Start queue worker
php artisan queue:work --timeout=60

# Keep it running with Supervisor (Linux/Production)
# See Supervisor config guide
```

## Issue: Email tidak terkirim di Production (200 OK tapi no email)

Jika API mengembalikan 200 OK tetapi email tidak sampai ke Brevo/inbox, lakukan checklist berikut:

### ✅ Checklist 0: Check Queue Status

**FIRST**, run the diagnostic:

```bash
php artisan debug:email-queue
```

If it shows "X jobs stuck in queue", that's your problem! See the queue solution above.

### ✅ Checklist 1: Configuration (.env)

```env
# Set queue to sync for email tester
QUEUE_CONNECTION=sync

# WAJIB di production
MAIL_MAILER=smtp

# Brevo SMTP Server
MAIL_SCHEME=tls
MAIL_HOST=smtp-relay.brevo.com
MAIL_PORT=587
MAIL_USERNAME=your-brevo-username@smtp-brevo.com
MAIL_PASSWORD=your-brevo-smtp-password

# Sender email HARUS terdaftar di Brevo
MAIL_FROM_ADDRESS="your-verified-sender@domain.com"
MAIL_FROM_NAME="Your Organization Name"
```

⚠️ **PENTING:**

- `QUEUE_CONNECTION=sync` ensures emails send immediately (don't use database for email testing)
- `MAIL_MAILER` default adalah `'log'` — jika tidak di-set, email akan ditulis ke log file, bukan dikirim
- `MAIL_SCHEME=tls` untuk port 587 (tidak boleh kosong/null)
- `MAIL_FROM_ADDRESS` HARUS terdaftar sebagai sender di Brevo, jika tidak email akan di-reject

### ✅ Checklist 2: Brevo Credentials

1. Login ke [Brevo Dashboard](https://app.brevo.com)
2. Navigate ke **SMTP & API > SMTP**
3. Verify:
   - ✓ SMTP relay enabled
   - ✓ Sender email verified di "Senders" tab
   - ✓ Generate SMTP credentials jika belum ada

### ✅ Checklist 3: Server Configuration

```bash
# Verify Laravel mail config ter-cache dengan benar
php artisan config:clear
php artisan config:cache

# Lihat logs untuk debug detail
tail -f storage/logs/laravel.log
```

### ✅ Checklist 4: Check Logs

Buka `/god-mode/error-log` atau check `storage/logs/laravel.log`:

```
[timestamp] production.INFO: Email Tester: Attempting to send test email to user@example.com
[timestamp] production.INFO: Email Tester: Successfully sent test email to user@example.com
```

**Jika error:**

```
[timestamp] production.ERROR: Email Tester: Failed to send test email to user@example.com:
Connection could not be established with host smtp-relay.brevo.com
```

### ✅ Checklist 5: Test via Email Tester

1. Buka `/god-mode/email-tester`
2. Check SMTP Config card di kiri — harus show:
   - Mailer: `smtp`
   - Host: `smtp-relay.brevo.com`
   - Port: `587`
   - Scheme: `tls`
3. Kirim test email
4. Response JSON akan show debug info:
   ```json
   {
     "success": true/false,
     "message": "...",
     "debug": {
       "mailer": "smtp",
       "host": "smtp-relay.brevo.com",
       "port": 587
     }
   }
   ```

## Common Errors & Solutions

### 1. "Mailer: log" di SMTP Config card

**Problem:** `MAIL_MAILER` tidak di-set di `.env`
**Solution:**

```env
MAIL_MAILER=smtp
```

Kemudian run:

```bash
php artisan config:clear
php artisan config:cache
```

### 2. "Connection could not be established with host"

**Problem:**

- Port tidak correct (gunakan 587 untuk TLS, 465 untuk SSL)
- Firewall blocking outbound SMTP
- SMTP relay tidak enabled di Brevo

**Solution:**

```bash
# Test SMTP connection
telnet smtp-relay.brevo.com 587

# Check DNS
nslookup smtp-relay.brevo.com
```

### 3. "Authentication failed"

**Problem:**

- `MAIL_USERNAME` atau `MAIL_PASSWORD` salah
- SMTP credentials expired di Brevo

**Solution:**

- Re-generate SMTP credentials di Brevo dashboard
- Verify username format: `username@smtp-brevo.com` (bukan email personal)

### 4. Email masuk spam

**Problem:** SPF/DKIM/DMARC tidak configured

**Solution:**

- Verify sender domain di Brevo
- Add SPF record: `v=spf1 include:smtp-relay.brevo.com ~all`
- Enable DKIM signing di Brevo

### 5. Brevo logs empty (email tidak reach Brevo at all) + "200 OK" tapi no email

**Problem:**

- Email di-queue dan queue worker tidak running ← **MOST COMMON**
- Email error sebelum sampai Brevo

**Solution:**

```bash
# First, check queue status
php artisan debug:email-queue

# If showing "X jobs stuck in queue" - THAT'S THE PROBLEM!
# Check if QUEUE_CONNECTION is set:
grep QUEUE_CONNECTION .env

# Should be 'sync' untuk email langsung terkirim:
QUEUE_CONNECTION=sync

# Then clear cache:
php artisan config:clear
php artisan config:cache

# If database queue, check jobs table:
php artisan tinker
>>> DB::table('jobs')->count()  # Should be 0 or small number
>>> DB::table('jobs')->where('created_at', '<', now()->subHours(1))->delete()  # Clean old stuck jobs

# If database queue, ensure queue:work is running:
php artisan queue:work --timeout=60
```

### 6. "force_sync: true" in Email Tester response

**Info:** Email Tester now **always uses sync queue** to bypass database queue, ensuring emails are sent immediately or fail immediately with real errors.

If response shows `"force_sync": true`, emails are being sent via sync connection (bypassing any queue configuration).

## Email Send Flow

```
User click "Kirim Test Email"
    ↓
POST /god-mode/email-tester/send
    ↓
EmailTesterController::send()
    ↓
Mail::to($email)->send(new TestEmail())
    ↓
[Log: "Attempting to send..."]
    ↓
Config check → MAIL_MAILER=smtp? MAIL_SCHEME=tls?
    ↓
Connect to smtp-relay.brevo.com:587 via TLS
    ↓
Authenticate with MAIL_USERNAME/MAIL_PASSWORD
    ↓
Send email from MAIL_FROM_ADDRESS
    ↓
[Log: "Successfully sent" or "ERROR: ..."]
    ↓
Return JSON response to frontend
```

## Production Debug Workflow

1. **Run Email Queue Diagnostic (FIRST):**

   ```bash
   php artisan debug:email-queue
   ```

   This shows:
   - Current queue driver
   - Number of stuck jobs (if any)
   - Recommendations

2. **Check config:**

   ```bash
   php artisan tinker
   >>> config('queue.default')
   >>> config('mail.default')
   >>> config('mail.mailers.smtp.host')
   >>> config('mail.mailers.smtp.port')
   ```

3. **Send test via artisan:**

   ```bash
   php artisan tinker
   >>> Mail::mailer('sync')->to('test@example.com')->send(new \App\Mail\TestEmail())
   >>> # Check storage/logs/laravel.log for errors
   ```

4. **Check logs:**

   ```bash
   tail -50f storage/logs/laravel.log | grep -i email
   ```

5. **Check jobs table (if using database queue):**

   ```bash
   php artisan tinker
   >>> DB::table('jobs')->count()
   >>> DB::table('jobs')->orderBy('created_at')->limit(5)->get()
   ```

6. **Monitor Brevo logs:**
   - Buka Brevo dashboard → Activity
   - Check "Sent", "Failed", "Bounced" tabs

## Email Queue (Advanced)

Jika menggunakan `QUEUE_CONNECTION=database`:

```bash
# Ensure queue worker is running
ps aux | grep "queue:work"

# If not running, start it:
php artisan queue:work --timeout=60

# Monitor queue:
php artisan queue:monitor

# Process all pending jobs:
php artisan queue:work --stop-when-empty
```
