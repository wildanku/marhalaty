## 📋 Architecture Overview

### Email Flow

```
User Action (RSVP/Payment)
    ↓
Controller (RsvpController/PaymentController)
    ↓
Job Dispatch (Queue Database)
    ↓
Queue Worker (Cron: php artisan queue:work database --once)
    ↓
Job Handler (SendEventRegistrationConfirmedEmail/SendEventRegistrationPendingPaymentEmail)
    ↓
BrevoApiService::send()
    ↓
HTTP POST → https://api.brevo.com/v3/smtp/email
    ↓
✅ Email delivered to recipient
```

### Queue Configuration

- **Driver:** Database
- **Processor:** Cron job running every minute
- **Command:** `* * * * * cd /var/www/marhalaty && php artisan queue:work database --once --max-jobs=10 >> storage/logs/queue-worker.log 2>&1`
- **Logs:** `storage/logs/queue-worker.log`

### Common Issues & Solutions

| Issue                                 | Cause                          | Solution                                             |
| ------------------------------------- | ------------------------------ | ---------------------------------------------------- |
| `Brevo API error: Invalid API key`    | BREVO_API_KEY not set or wrong | Set correct key in .env, run config:cache            |
| `Connection refused to api.brevo.com` | Network/firewall blocking      | Check firewall allows outbound HTTPS (port 443)      |
| Emails not arriving after 5 min       | Queue worker not running       | Check cron job, verify `queue:work` is executing     |
| Job stuck in queue indefinitely       | Queue worker crash             | Check logs, restart cron, verify database connection |
| Email looks broken/unformatted        | HTML encoding issue            | Check `$rsvp->user->name` doesn't have special chars |

## 🎯 Root Cause Resolution

**Problem:** Production emails returning 200 OK but not arriving  
**Identified Root Cause:** SMTP connection timeout to smtp-relay.brevo.com:587 (firewall/ISP blocking port 587)  
**Solution:** Migrated entire email system from SMTP to Brevo REST API (HTTP POST, no port restrictions)  
**Status:** ✅ Implementation complete, bypasses firewall completely

---

## ✨ Benefits of This Approach

1. **No Firewall Issues** - Uses standard HTTPS (port 443), not blocked by firewalls
2. **Queue-Based Reliability** - Database queue + cron ensures no emails are lost
3. **Full Audit Trail** - All sent emails logged with message IDs
4. **Easy Testing** - Email Tester admin panel for quick verification
5. **Scalable** - Batch sending capability for mass emails in future
6. **Provider Agnostic** - Can easily switch to different API provider if needed
