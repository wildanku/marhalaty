# Email Queue Configuration & Deployment

## Current Status: How Emails Are Being Sent

### Real Application Emails (Event Registration, Payments)

**All emails in this project use database queue:**

```php
// app/Domains/Event/Controllers/RsvpController.php
Mail::to($user->email)->queue(new EventRegistrationConfirmed($rsvp));

// app/Domains/Event/Controllers/PaymentController.php
Mail::to($rsvp->user->email)->queue(new EventRegistrationConfirmed($rsvp));
```

**Email Flow:**

```
User triggers event → Mail::queue() → Jobs table → Queue Worker reads jobs → Email sent to Brevo
```

### Configuration

- **Queue Driver:** `database` (default in `.env`)
- **Queue Table:** `jobs` (auto-created by Laravel)
- **Queue Worker Status:** Run `php artisan debug:email-queue` to check

## Two Approaches for Production

### ✅ APPROACH 1: SYNC QUEUE (Simple, Recommended for Small Projects)

**Pros:**

- ✓ Emails send immediately
- ✓ No queue worker needed
- ✓ Simple error handling
- ✓ No failed job tracking

**Cons:**

- ✗ If SMTP down, email request blocks the user request
- ✗ Requires Brevo to be fast (usually <100ms)

**Setup:**

```bash
# 1. Update .env
echo "QUEUE_CONNECTION=sync" >> .env

# 2. Clear config cache
php artisan config:clear
php artisan config:cache

# 3. Verify
php artisan debug:email-queue
# Should show: "Mailer: smtp" (no queue worker needed)
```

---

### ✅ APPROACH 2: DATABASE QUEUE WITH SUPERVISOR (Recommended for Production)

**Pros:**

- ✓ Emails always queue, never block user request
- ✓ Failed jobs are retried automatically
- ✓ Queue worker restarts automatically if crashes
- ✓ Better for high-traffic applications

**Cons:**

- ✗ Requires supervisor process running 24/7
- ✗ More complex setup
- ✗ Needs monitoring

**Setup on Ubuntu:**

#### Step 1: Install Supervisor

```bash
sudo apt-get update
sudo apt-get install supervisor -y
```

#### Step 2: Create Queue Worker Config

```bash
sudo nano /etc/supervisor/conf.d/laravel-worker.conf
```

Paste this configuration:

```ini
[program:laravel-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /var/www/marhalaty/artisan queue:work database --sleep=3 --tries=3 --timeout=90
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
numprocs=1
redirect_stderr=true
stdout_logfile=/var/log/laravel-worker.log
stopwaitsecs=3600
environment=PATH="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin",HOME="/root",LOGNAME="root"
```

**Key Parameters:**

- `--sleep=3` — Wait 3 seconds before checking for new jobs
- `--tries=3` — Retry failed jobs up to 3 times
- `--timeout=90` — Maximum 90 seconds per email (Brevo + network)

#### Step 3: Enable & Start Supervisor

```bash
# Update supervisor config
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl start laravel-worker:*

# Check status
sudo supervisorctl status

# View logs
tail -f /var/log/laravel-worker.log
```

#### Step 4: Check Production Queue Status

```bash
# SSH into production server
ssh user@your-server.com

# Check if queue worker is running
sudo supervisorctl status laravel-worker

# If not running, start it
sudo supervisorctl start laravel-worker:*

# Check for stuck jobs
php artisan debug:email-queue
```

#### Step 5: Monitor Queue Health

```bash
# Check pending jobs
php artisan tinker
>>> DB::table('jobs')->count()  # Should be close to 0

# Check failed jobs
>>> DB::table('failed_jobs')->count()  # Should be 0 or very low

# If many failed jobs
>>> DB::table('failed_jobs')->latest()->limit(10)->get()
```

## Alternative: CRON JOB (Not Recommended)

If you prefer cron instead of supervisor:

```bash
# Edit crontab
crontab -e

# Add this line (runs every minute)
* * * * * php /var/www/marhalaty/artisan queue:work database --once --max-jobs=10
```

**Issue:** If Laravel process dies, cron won't detect it. Use supervisor instead.

## Debugging Queue Issues

### Check if queue worker is running

```bash
# On production server
ps aux | grep "queue:work"

# Or use supervisor status
sudo supervisorctl status laravel-worker
```

### View queue worker logs

```bash
tail -f /var/log/laravel-worker.log
```

### Check jobs table for stuck jobs

```php
php artisan tinker

// Total pending jobs
DB::table('jobs')->count()

// Stuck jobs (created more than 1 hour ago)
DB::table('jobs')
  ->where('created_at', '<', now()->subHours(1))
  ->count()

// Oldest 5 jobs
DB::table('jobs')
  ->orderBy('created_at')
  ->limit(5)
  ->get(['id', 'queue', 'created_at', 'attempts'])

// Delete stuck jobs (use carefully!)
DB::table('jobs')
  ->where('created_at', '<', now()->subHours(1))
  ->delete()
```

### Check failed jobs

```php
// View all failed jobs
DB::table('failed_jobs')->get()

// Retry all failed jobs
php artisan queue:retry all

// Or retry specific ID
php artisan queue:retry 1
```

## Performance Tips

### 1. Reduce Queue Worker Sleep Time (for faster delivery)

```ini
# /etc/supervisor/conf.d/laravel-worker.conf
command=php /var/www/marhalaty/artisan queue:work database --sleep=1 --tries=3 --timeout=90
#                                                                           ↑ Faster checks (1 sec)
```

### 2. Increase Number of Workers (for high volume)

```ini
[program:laravel-worker]
numprocs=4  # Run 4 worker processes instead of 1
```

Then restart:

```bash
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl restart laravel-worker:*
```

### 3. Monitor Queue Depth

```bash
# Create a cron job to monitor queue health
*/5 * * * * php /var/www/marhalaty/artisan queue:monitor 2>&1
```

## Production Deployment Checklist

- [ ] Set `QUEUE_CONNECTION=database` (or `sync` if using sync approach)
- [ ] Run `php artisan migrate` (creates `jobs` table)
- [ ] Install supervisor: `sudo apt-get install supervisor`
- [ ] Create `/etc/supervisor/conf.d/laravel-worker.conf`
- [ ] Run `sudo supervisorctl reread && sudo supervisorctl update`
- [ ] Start queue worker: `sudo supervisorctl start laravel-worker:*`
- [ ] Verify: `php artisan debug:email-queue`
- [ ] Test email: Send event registration and check Brevo logs
- [ ] Monitor logs: `tail -f /var/log/laravel-worker.log`

## Quick Decision Matrix

| Scenario                                 | Recommendation                          |
| ---------------------------------------- | --------------------------------------- |
| **Small project, low volume**            | SYNC queue (`QUEUE_CONNECTION=sync`)    |
| **Production, high reliability needed**  | DATABASE queue + Supervisor             |
| **Testing locally**                      | Either (database queue is fine locally) |
| **Email delivery must be instant**       | SYNC queue (blocks on SMTP errors)      |
| **Can tolerate delay, need reliability** | DATABASE queue + Supervisor             |
